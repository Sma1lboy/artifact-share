Cloudflare Worker + KV · ~200 lines

Publish an HTML page. Get the verdicts back.

Your agent builds a self-contained page — a review board, a diff, a report — and POSTs it. Out comes a public link anyone can open. They decide in the browser; the agent reads those decisions back as JSON. No account, no build step, no dashboard to log into.

Read the API Source on GitHub

1 · Publish

POST /share

Body is your HTML, up to 4 MB. The id is a hash of the content, so republishing the same page returns the same link.

→

2 · Review

GET /share/<id>

Anyone with the link opens the page and submits their decisions. Drafts sit in their browser until they send.

→

3 · Collect

GET /share/<id>/verdicts

One JSON blob, merged across reviewers and keyed by name. The agent reads it directly — no copy-paste shuttle.

Four endpoints

That is the whole surface. Everything is public by design: unguessable ids, short lifetime, nothing worth stealing after a day.

POST /share
?series=&round=&title=&by=
Publish a page (body = HTML, ≤4 MB) → {id, url}. Content-derived id, so republishing is idempotent. Passing series files it under a stable slug.
GET /share/<id>
Serve the page and re-arm its expiry. 410 once it has lapsed. With ?series= a thin topbar is prepended for round history — your HTML is never rewritten.
POST /share/<id>/verdict
One reviewer's submission: {name, decisions[], next?}. Keyed by name, so resubmitting overwrites rather than duplicates.
GET /share/<id>/verdicts
Every submission merged: {id, count, submissions[]}. This is the endpoint an agent polls.
GET /s/<slug>
One stable URL per series — redirects to the newest round, so a link you shared last week still lands on today's page. /s/<slug>/index.json lists the history.

The whole round trip

Two commands to ship a board and read what came back.

# publish — the link is the response $ curl -X POST https://share.sma1lboy.me/share?series=logo&round=3&by=jackson \ --data-binary @board.html {"id":"a3f10c88b2e94d71","url":"https://share.sma1lboy.me/share/a3f10c88b2e94d71?series=logo"} # …reviewers open it, click, submit… # collect — one blob, merged by reviewer $ curl https://share.sma1lboy.me/share/a3f10c88b2e94d71/verdicts {"id":"a3f10c88b2e94d71","count":2,"submissions":[ {"name":"jackson","decisions":[{"item":"r3-01","verdict":"keep"}],"next":"tighten the counter"}, {"name":"wei","decisions":[{"item":"r3-04","verdict":"kill"}]}]}

What it deliberately doesn't do

The constraints are the product. Each one is why it stays about 200 lines.

expires in 24h idle

Nothing is permanent

Every key carries a one-day TTL. Any hit re-arms it, so an active review lives on and an abandoned one disappears. Republish the same content to bring a dead link back.

No accounts

No login, no roles, no invites. Reviewers type their name when they submit. Links are unguessable 64-bit content hashes; treat them as capability tokens and share them like you'd share a doc link.

No renderer

The server stores bytes and hands them back. Your page must be self-contained — inline CSS, inline SVG, data-URI images. No bundler, no framework, no asset pipeline to keep alive.

No dashboard

There is no place to log in and browse your shares. The agent that published a link is the thing that reads it back, and a series slug is the only index that exists.

Run your own

One Worker, one KV namespace. It fits in the Cloudflare free tier and there is nothing else to operate.

$ git clone https://github.com/Sma1lboy/artifact-share $ cd artifact-share $ bunx wrangler kv namespace create SHARES # paste the id into wrangler.toml $ bunx wrangler deploy

Point routes at your own hostname, or drop the block entirely and use the *.workers.dev subdomain. The landing page you're reading is served from site/ by the same Worker.

Where it came from

Built for brand-studio, which needed to put a round of generated logo candidates in front of several people and read the keep/kill decisions back without anyone opening a tool. It turned out that nothing about that is specific to brand assets — so it's its own thing now, and brand-studio consumes it as a submodule.
